# Risk zones — read before editing

> A checklist of danger areas for engine and Arcopolis work. Each item: the danger, where it lives,
> and what to do before editing. Not exhaustive — when in doubt, read the code and tests.

## 1. Arcopolis protected architecture + backend-UI invariant

- **Danger:** the backend must create **no curses window and call no render primitive in any build**,
  and must drive real registered inputs through the engine's own input loop — not shortcuts or direct
  state mutation. Violating this silently breaks the fidelity/equivalence contract.
- **Where:** `AGENTS.md:56` and `AGENTS.md:61-128`; full rules in
  `docs/arcopolis/40_SPIKE19_BACKEND_UI_BOUNDARY.md`; the seam guard `backend_session_active()`
  (`src/arcopolis_backend_input.cpp:528`) and the per-transaction un-abort gates referenced from
  `src/arcopolis_backend_input.h`.
- **Before editing:** read `docs/arcopolis/ARCOPOLIS_STATE.md` and the Spike 19 boundary doc; gate any
  new un-abort on its **own** per-transaction predicate, never a sibling's.

## 2. Renderer / curses / `test_mode` hazards

- **Danger:** the backend runs in `test_mode` with no interface initialized. `catacurses::newwin`
  is the **real ncurses `::newwin`** in curses builds (`src/ncurses_def.cpp:71-74`) and is fatal
  before `initscr`. `uilist` short-circuits to `UILIST_ERROR` under test_mode
  (`src/ui.cpp:935`, constant at `src/ui.h:25`), so a nested-input guard can never see it.
- **Where:** `src/ncurses_def.cpp:71-74`, `src/ui.cpp:935`, `AGENTS.md:56`.
- **Before editing:** when un-aborting a `test_mode`-gated UI loop, run data population but **skip
  window creation**; a tiles-only regression will not catch a curses-build `newwin` crash.

## 3. Save/load & serialization compatibility

- **Danger:** the save wire format is versioned. Changing how `item`/`Character`/`npc`/`map` state
  serializes can silently corrupt or fail to load existing saves unless the version is bumped and a
  migration path is added.
- **Where:** `const int savegame_version = 29` at `src/savegame.cpp:66`; backward-compat branches keyed
  on `savegame_loading_version` throughout `src/savegame_json.cpp` (e.g. `:1243`, `:1271`, `:2903`,
  `:3262`).
- **Before editing:** if you change a serialized layout, bump `savegame_version` and add a guarded
  migration branch; test loading an old save.

## 4. Generated files — do not hand-edit

- **Danger:** several files are produced by the build/tooling; hand edits get overwritten or go stale.
- **Where:**
  - `src/version.h` — generated from git: written directly by `CMakeLists.txt:104-125`, and also
    regenerated from the `src/version.h.in` template via `src/CMakeLists.txt:42-49`.
  - `lua_annotations.lua` and `docs/en/mod/lua/reference/lua.md` — generated by `deno task docs:gen`
    (`deno.jsonc:13`).
  - `data/shaders/*` — compiled from `src/shaders/*.hlsl` (`CMakeLists.txt:516-622`).
  - `lang/mo/*` — compiled translations.
- **Before editing:** edit the source/template or rerun the generator; never edit the artifact.

## 5. Object ownership / memory model (game objects)

- **Danger:** items (and other "game objects") use private constructors and a move-only
  `detached_ptr` ownership model with `safe_reference`/`cache_reference` for stored references. Holding
  a raw pointer/reference across turns, or copying a game object, is a bug (often a debugmsg + null
  object, or worse).
- **Where:** `src/detached_ptr.h`, `src/safe_reference.h`, `src/game_object.h`, `src/cata_arena.h`,
  `src/locations.h`; explained in `docs/en/dev/explanation/game_objects.md`.
- **Before editing:** read `game_objects.md`; use `detached_ptr` for objects in transit and
  `safe_reference` for stored references; do not store raw `item*` across turns.

## 6. Huge translation units / compile-time / merge risk

- **Danger:** a few files are enormous and slow to compile, and are frequent merge-conflict sites on
  upstream sync.
- **Where:** `src/mapgen.cpp` (~285 KB), plus large `src/game.cpp`, `src/character.cpp`, `src/item.cpp`.
- **Before editing:** keep changes localized; expect long rebuilds; on upstream merges re-check these
  files carefully.

## 7. Threading / async / global state

- **Danger:** parts of the engine run off the main thread or via a pool; plus the global `g` singleton
  is shared mutable state. Naive changes can race or assume single-threaded execution.
- **Where:** `src/thread_pool.cpp/.h`, `src/mapgen_async.cpp`, parallel work in
  `src/shadowcasting.cpp` and `src/lightmap.cpp`, the GPU compute queue in `src/compute/`; global
  `game *g` (`src/game.h:62`).
- **Before editing:** check whether the code path runs async before touching shared state; prefer the
  existing seams.

## 8. JSON IDs — `string_id` vs `int_id` stability

- **Danger:** content is loaded via `generic_factory`, which assigns each `string_id` a cached
  `int_id` (a load-order index). `int_id` values are **not stable across loads** and must not be
  persisted as raw integers; the string id is the durable key.
- **Where:** `src/generic_factory.h`, `src/string_id.h`, `src/int_id.h`, `src/type_id.h`;
  loaders registered in `src/init.cpp`.
- **Before editing:** persist/compare by `string_id`; treat `int_id` as a within-session fast index.

## 9. Build cache / stale objects

- **Danger:** ccache can serve a stale object for an unchanged `.cpp` whose included header changed
  (struct-layout ABI mismatch → crashes in code you did not touch).
- **Where:** ccache configuration and worktree notes in `AGENTS.md:151-157` and the build docs.
- **Before editing:** if you hit an unexplained crash after a header change, suspect stale ccache
  objects (clear cache + rebuild the includers) before chasing a "real" bug.

## 10. Upstream merge-collision zones (Arcopolis hooks)

- **Danger:** the fork inserts backend hooks at the head of several engine dispatch paths; these
  recur as merge conflicts (and one literal silently mis-merges) on upstream sync.
- **Where:** `AGENTS.md:46` — `src/main.cpp` (CLI arg array), `src/handle_action.cpp` (the backend
  input branch — guard at `src/handle_action.cpp:1778`, call at `:1779`), `src/input.cpp`
  (nested-input hook); the `do_turn`
  clean-park in `src/game.cpp`.
- **Before editing/merging:** follow the `AGENTS.md:46` sync workflow; after any sync that adds a CLI
  arg, fix the `<arg_handler, N>` count by hand.
