## The standard

A surface **passes** (earns a "faithful" verdict) only when it reproduces the GUI behavior for what
it claims to do — including any **deliberate, source-justified exclusion that is recorded** (e.g.
examine excludes vertical because `game::examine` passes `allow_vertical=false`). Partial coverage of
a GUI primitive while presenting _as_ the primitive is a **violation**, not an "acceptable
limitation," regardless of documentation — disclosure is not compliance. A wholly-unbuilt command
(talk, pickup, open/close) is honest **backlog**, distinct from a violation, because it does not
present as a complete primitive it then under-delivers.

## Open items this audit records (so they are not silent)

- **`move` vertical** (`move_up/down`): **no longer a future item — implemented as the SEPARATE
  `vertical_move` verb** (directions `down`/`up` → `ACTION_MOVE_DOWN`/`ACTION_MOVE_UP` → native
  `game::vertical_move`), NOT a widening of planar `move` (Spike 24, matched-stair only, level 2/3; doc 49).
  Other vertical paths (ramp/rope/climb/elevator) can still open their own prompts and stay deferred.
- **menu interaction depth**: **pickup-as-an-action is now implemented** — the `pickup` command's
  level-4 prompt/menu transaction (Spike 12A, doc 30) builds doc 25's Option C for the old `"PICKUP"`
  menu, including **multi-entry selection** (one `RIGHT` per chosen entry; carry-both witnessed on the
  `ArcopolisBackpackTest` fixture, and the over-capacity rejection — item left on the ground, never faked as
  picked up — witnessed on `ArcopolisTest`).
  Still deferred: NPC talk/attack/swap and computer use (each needs its own menu driven the same way, or a
  raw-read guard), the `NEW_PICKUP_MENU` inventory_selector, **per-unit quantity entry** (a tracked defect —
  whole-stack only), driving the in-activity capacity/wield/spill prompts, and a nested-container witness
  (container entries are now exposed, and the engine _would_ handle parent/child marking, but no fixture
  entry has child sub-entries — so that path is currently unexercised and unwitnessed, an open defect).
- **`open`/`close`/`smash`** verbs — the near-free examine follow-ups.
- ~~**Frontend diagonal click-move**~~ — **closed (Spike 11B)**: the click mapping + 3×3 d-pad now
  cover all 8 neighbors and a Move/Examine selector adds 8-way-plus-`here` examine; the frontend row
  above is now **faithful** for the planar move/examine surface. See doc 29.
- **`npctalk` raw dialogue read** (`src/npctalk.cpp`) — a direct `get_input_event` reader not reachable
  today (examine's NPC menu auto-cancels first); the future `talk` verb must guard it before exposing
  dialogue (recorded in [27_BACKEND_RAW_WAIT_GUARD.md](27_BACKEND_RAW_WAIT_GUARD.md)).
